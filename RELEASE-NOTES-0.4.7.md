# javacard-rpc 0.4.7

The facade accepts the explicit persistent cleanup selector
`stream_workspace_cleanup = "whole-reply-area"`. Successful request writes are
tracked; once a handler runs, cleanup covers its entire authorized reply area,
including scratch beyond the returned length. Untouched workspaces incur no
cleanup stores. Handlers retain the raw array API and in-place request/reply
aliasing contract; they must stay within authorized ranges and must not retain
workspace aliases after returning.

```toml
[applet]
stream_workspace = "persistent"
stream_workspace_cleanup = "whole-reply-area"
```

`written-bytes-only`, unknown selectors and nonpersistent combinations fail
semantic validation before output mutation. Omitted or empty cleanup preserves
v0.4.6 generated bytes, including existing persistent schemas. Reset behavior,
session ownership, wire protocol and Kotlin/Swift pins are preserved.

Exact signed tag objects and backend imports are in the
[runtime manifest](compatibility/runtime-manifest.json). Use
[verified local runtime substitutions](compatibility/README.md) to select these
versions while retaining historical generated ecosystem coordinates. Go
consumption uses `GOWORK=off` and no production replacements. API v0.1.1's unused
written-mode constant remains a compatibility symbol, not a supported mode.

The [Java Card cleanup cost comparison](https://github.com/relux-works/javacard-rpc-server-javacard/blob/v0.3.1/PERSISTENT-WORKSPACE-COSTS.md)
retains the rejected writer experiment and real Auth measurements. That SDK
bridge required 2048 B staging and added 2060 B attributed RAM and 1912 B CAP
against whole mode. Whole-mode counters cover instrumented Auth/generated
stores; provider-written output outside the observer is omitted and bounded by
actual output lengths. These figures establish no exact total NVM advantage,
physical wear, timing, torn-write atomicity or total card RAM claim. The whole
generated Auth production files retain their measured source identities.

The [IDL contract](.spec/idl.md#52-bulk-workspace-storage-policy) describes the
raw handler and cleanup bounds. Swift stream generation remains unsupported and
refuses before writes; Java Card and Kotlin retain their supported lanes.
